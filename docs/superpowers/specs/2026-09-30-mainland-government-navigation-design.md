# 中国大陆政府机构官网导航：设计规格

- 日期：2026-09-30
- 状态：设计已在对话中确认，等待规格审阅
- 目标仓库：`gov-nav`
- 部署方式：GitHub Pages

## 1. 项目目标

构建一个无需后端即可运行的中国大陆政府机构官网静态导航页。站点同时提供国家级、省级、地市级、县区级机关官网入口，并支持：

- 按行政区逐级浏览。
- 按机关名称、地区、域名和类别进行全局搜索。
- 查看官网链接的来源、核验状态和最后核验时间。
- 通过 GitHub Actions 自动化校验数据、检查链接并部署。
- 在框架稳定后分批补全海量机关数据，而不需要重构数据层或页面结构。

## 2. 范围

### 2.1 收录范围

- 行政区划范围：中国大陆，不包含香港、澳门和台湾。
- 层级范围：国家级、省级、地市级、县区级。
- 机关范围：党委、人大、政府、政协、法院、检察院、群团、政府工作部门及其他公共机构官网。
- 首批数据优先保证国家级入口、31 个省级入口以及省、市、县三级政府门户的完整性。
- 后续按“省级机关、地市机关、县区机关、各部门”的顺序分批补全。

### 2.2 非目标

首版不包含：

- 服务端、数据库或在线 CMS。
- 抓取和镜像机关网站正文内容。
- 在线地图、地理编码或导航路线。
- 自动判断链接是否“权威”，权威性仍由来源和人工审核决定。
- 对反爬、验证码或临时故障作出强制失效结论。

## 3. 信息架构

### 3.1 首页

- 全局搜索框。
- 国家级机关目录入口。
- 31 个省级行政区入口。
- 当前数据覆盖统计与最近核验时间。
- 数据说明与纠错入口。

### 3.2 国家级页

按以下类别展示全国性机关：

- 党中央部门及直属机构。
- 全国人民代表大会。
- 国务院及组成部门、直属机构。
- 全国政协。
- 最高人民法院、最高人民检察院。
- 全国性群团组织及其他机构。

### 3.3 地方页

- 省级页：省级机关与部门，以及所辖地市入口。
- 地市页：地市级机关与部门，以及所辖县区入口。
- 县区页：县区级机关与部门，按统一类别分组。
- 面包屑始终提供返回上级区域的路径。

### 3.4 搜索结果

结果展示：

- 机关名称。
- 网站名称。
- 省、市、县层级与地区。
- 机关类别。
- 官网域名。
- 链接核验状态。

结果支持按层级和类别过滤，并可复制网址或在新标签页打开。

## 4. 技术架构

### 4.1 前端

- Vite + TypeScript 构建纯静态站。
- 使用轻量级原生 DOM/组件实现，首版不引入重型 UI 框架。
- 使用 hash 路由，确保 GitHub Pages 无需服务端重写规则即可访问全部页面。
- 样式使用 CSS 变量和响应式布局，支持桌面与移动端。
- 交互支持键盘操作、可见焦点、语义化标题与可读的链接状态文本。

### 4.2 数据层

数据源文件：

- `data/regions.json`：省、市、县行政区名称、行政区划代码、层级和父子关系。
- `data/national.json`：国家级机关记录。
- `data/provinces/<省级代码>.json`：省级、地市级和县区级机关记录。
- `data/generated/link-status.json`：链接检查生成结果，不进入人工维护数据。
- `public/search-index/`：构建期生成的分片搜索索引。

国家级使用稳定标识 `CN`，不与省级行政区划代码混用。省级及以下使用国家标准行政区划代码作为稳定标识。

### 4.3 机关记录字段

```ts
type AgencyRecord = {
  id: string;
  regionCode: string;
  name: string;
  siteName: string;
  url: string;
  category:
    | 'party'
    | 'people_congress'
    | 'government'
    | 'cppcc'
    | 'court'
    | 'procuratorate'
    | 'mass_org'
    | 'department'
    | 'other';
  subcategory?: string;
  sourceUrl: string;
  tags?: string[];
  note?: string;
};
```

约束：

- `id` 全局唯一且稳定，默认由地区代码、类别和名称 slug 组成。
- `regionCode` 必须指向 `regions.json` 中的有效地区，或为国家级标识 `CN`。
- `url` 优先使用 HTTPS，但允许保留只支持 HTTP 的官方地址。
- 域名必须匹配机关官网或明确可信的官方来源页面。
- 来源不可确认的记录必须带 `note`，不得伪造官网地址。

### 4.4 链接状态

链接检查结果按记录 ID 保存：

```ts
type LinkStatus = {
  id: string;
  status: 'valid' | 'invalid' | 'unknown';
  httpStatus?: number;
  checkedAt: string;
  detail?: string;
};
```

判定规则：

- `200-399`：`valid`。
- `404`、`410`：`invalid`。
- `403`、429、超时、DNS 临时异常、TLS 异常：`unknown`，等待人工复核。
- 自动检查不得直接删除记录；失效或未知状态通过报告与 PR 提醒维护者。

## 5. 数据构建与发布流程

### 5.1 PR 检查

每个 Pull Request 执行：

1. 类型检查与代码规范检查。
2. 数据 Schema 与引用完整性校验。
3. 单元测试和关键页面端到端测试。
4. 生产构建验证。

只有全部通过的 PR 才能合并到默认分支。

### 5.2 GitHub Pages 部署

- 默认分支合并后，由 GitHub Actions 构建并发布静态产物。
- `base` 路径兼容 GitHub Pages 项目站点地址，也允许后续绑定自定义域名。
- 页面运行时只读取静态 JSON，不依赖第三方 API。

### 5.3 定时链接检查

- 每周一北京时间 02:00 执行，对应 UTC 每周日 18:00。
- 检查结果写入生成数据，并生成或更新维护报告。
- 发现失效链接时生成 GitHub Issue；自动任务不直接修改人工维护的官网地址。

## 6. 搜索与性能

- 首页仅加载地区摘要、国家级索引和搜索所需的轻量数据。
- 省级机关数据按省分片，进入对应省份后加载。
- 搜索索引按省分片，并通过构建脚本生成。
- 搜索支持中文名称、行政区名称、分类和域名的模糊匹配。
- 首屏 JS 预算目标：gzip 后不超过 250 KB。
- 首屏不得一次性加载全部机关数据。

## 7. 错误与空状态

- 数据加载失败：显示重试操作和明确错误信息。
- 搜索无结果：展示搜索建议与热门分类。
- 地区尚无完整机关数据：显示“框架已建立，数据待补全”，不显示空白页。
- 链接状态未知：显示“待核验”，不得误标为失效。
- URL 缺省或异常：构建校验应阻止发布，而非在页面运行时静默忽略。

## 8. 测试策略

- 数据校验器单元测试：字段、枚举、唯一性、父子关系和行政区代码。
- URL 规范化与状态映射测试。
- 搜索、过滤和路由状态测试。
- 使用 Playwright 验证首页、国家级页、省/市/县页和搜索结果页。
- GitHub Actions 中验证生产构建与 GitHub Pages 相对路径资源。
- 链接检查器使用模拟响应测试，避免测试依赖外部网站实时状态。

## 9. 成功标准

- 可访问国家级页、31 个省级页以及后续导入的地市、县区页。
- 可通过名称、地区、类别和域名找到官网入口。
- 数据文件可独立按省维护，新增数据不会要求修改页面实现。
- 数据校验、测试和部署可完全在 GitHub 上运行。
- 记录能显示来源和核验状态，且不会将不确定状态误报为失效。
